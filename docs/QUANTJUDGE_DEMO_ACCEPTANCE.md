# QuantJudge：隐私边界与模拟交易验收

2026-09-11，工作分支 `QuantJudge`。

## 当前能否对平台开发者隐藏策略？

还不能对任意上传策略作此承诺。

- `backend/app/zkp.py` 调用本机 RISC Zero 验证器并固定 image ID。受限整数程序作为私密 witness 在开发者本机证明，平台接收 receipt；这条路径能够证明指定输入与成本模型下的计算，不能证明交易所真实成交或收益数据来源。
- `backend/app/tee.py` 有 AWS Nitro 证书链、COSE 签名、PCR、nonce 与通道公钥校验；返回值明确为 `performance_verified=false`。尚缺真实 Enclave 部署、客户端加密上传和证明后密钥释放、机密策略执行与输出绑定。普通上传包由 `strategy_studio.py` 的平台密钥解密，平台运营方可以读取。
- 本次测试策略走后端规则执行器，源码公开用于联调，不声称这条运行路径已经具备 TEE/ZKP 隐私保护。

真正的机密执行需要：独立可信的客户端验证被审核的 Enclave 测量值后才释放策略解密密钥；Enclave 内执行策略，受限地使用交易 API，输出绑定策略版本、输入行情、账户范围、交易所成交、费用、现金流与估值时间的报告。网页由平台任意替换时，仅把加密放进该网页还不能防范恶意平台窃取上传内容。还需要独立验证客户端或可校验的发行与更新信任链。

收益“准确”必须先约定范围。ZKP 证明计算关系，不能把伪造的成交输入变成真实成交；TEE 证明运行环境也不能保证未来盈利。需要可信数据摄取、完整成交与费用对账、存取款口径、估值覆盖和第三方复核。公开收益、订阅者的成交和持仓仍可能泄露策略特征。

## Supervisor 上启动什么？

现有链集成为 JSON-RPC 客户端（默认 127.0.0.1:42515，预期 chain ID 1051）。当前源码的入口调用 `build.BuildSupervisor`；必须同时具备其实际依赖的网络、节点和数据库。不要只启动一个监督进程就宣称具备去中心化验证。现有节点是否在线需要另行查询 RPC，本次未启动或修改 Supervisor。

现有 Atlas 流程：开发者本地证明 → 后端验证 receipt → 外部钱包签名 → Supervisor 锚定 `ATLASZK2` 及 receipt/proof/public-input/nullifier 哈希。当前只是存证，链上没有执行 RISC Zero verifier。

生产链上应部署并运行策略版本/承诺登记、订阅授权与结算、证明验证与防重放、报告登记合约；在确认这条链支持的 VM 与验证成本后，选择兼容的证明验证实现。策略源码、API secret、完整 witness 不上链；策略 runner、交易所适配器、TEE 和证明者在链外运行。单一运营方控制节点、验证器和前端仍不等于去中心化。

## 本次代码路径

1. **策略中心 → 策略市场 → 可运行策略**：点击“添加并订阅连通性测试策略”。创建真实不可变规则版本与订阅，规则来自 `strategy/examples/exchange-demo/release.json`。
2. **策略交易**：选择该订阅、CRYPTO、交易所测试、对应 Binance/OKX 测试账户、BTC-USDT、15 分钟、例如 200 USDT 分配资金，勾选自动执行模拟订单并启动。
3. 首次 tick 只建立已闭合 K 线基线；下一根已闭合行情产生建议。执行器按测试交易所价格和精度创建限价单，使用现有预算、余额、账户指纹和订单持久化检查。200 USDT、10%目标仓位时首笔目标约20 USDT，最终受费用、精度和交易所规则限制。
4. 后台对账以交易所成交 ID 去重，记录真实成交价格与费用。交易界面查看净值、快照最大回撤、持仓、成交及订单状态；资产总览显示策略资金，详情页展示账户余额与成交。测试资金和实盘资金分开，策略预算不重复加到手工资产。

自动执行仅限 `exchange_test` 且每个实例主动选择 `demo_auto=true`。同一信号只尝试一次，重启不重发；未完成/未知订单阻止下一笔。GTC 限价单不保证成交，未成交时需要查询或撤单。拒单、配置变更或未知结果暂停实例进入待处理状态。恢复不自动重试原信号。暂停/停止不自动清仓，已存在订单仍须查询或撤销。

页面配置现支持每位登录用户各自保存一个币安和一个欧易模拟账户，密钥按用户加密绑定；实盘环境变量接入仍是单一指定所有者模式。尚未进行公网多租户托管的生产验收，也未实现券商执行系统。策略资金收益也不等于整个交易所账户完整历史收益。

## 凭据与环境

推荐直接使用下方页面配置；无需设置环境变量。兼容旧终端方式时，在后端启动环境中配置 `ATLAS_TRADING_OWNER_ID`、`ATLAS_TRADING_ENABLED=1`、`ATLAS_TRADING_LIVE_ENABLED=0`、两个交易所 `MODE=demo`，以及对应模拟密钥。完整变量见 [交易账户接入](TRADING.md)。本地 `scripts/dev.sh` 不会自动加载任意 `.env` 文件，需先在启动终端导出变量。

币安这里接的是 [Spot Testnet](https://github.com/binance/binance-spot-api-docs/blob/master/testnet/general-info.md)，并非任意币安模拟产品的通用密钥；欧易使用 [Demo Trading API](https://www.okx.com/docs-v5) 与 `x-simulated-trading: 1`。模拟账户须由用户在对应交易所创建。不要把密钥发送到聊天、前端环境变量或源码仓库。

## 验收边界

自动化测试覆盖真实后端规则解释器的发布、订阅、执行、资产入账及跨用户隔离；交易所替身测试覆盖两种 venue 的自动提交、真实成交字段对账、重复调用/重启去重、切换实盘拒绝、超时不重发。测试替身不构成交易所成交凭证。

尚未取得用户测试 API 凭据，不能确认账户连接或真实模拟成交；尚未完成三个页面上的交易所真实成交闭环。TEE 硬件机密执行、交易所收益证明与链上 verifier 也未由本次改动实现。不能把本文件或测试通过作为这些能力的上线声明。

### 页面配置（当前推荐入口）

在「策略交易」展开「接入模拟交易账户 · 币安 / 欧易」，填写对应模拟API Key、Secret和欧易Passphrase，勾选模拟用途并点击「验证连接并保存」。后端只请求官方模拟账户查询接口，验证失败不保存；成功后加密持久化、清空前端密码字段，立即创建当前用户的测试账户并尝试同步资产，无需终端配置或重启。

每个用户的密文使用所有者、交易所及demo模式作为认证绑定；主密钥保存在数据目录的`.demo-account-key`，备份需连同该文件保护。静态加密不等于TEE，平台主机管理员仍可解密。原账户有运行实例、持仓或未完成订单时不允许换到另一组密钥。可运行策略成为策略市场默认页，报告页默认排除演示样本。

用户尚未创建交易所测试密钥。因此真实模拟交易所的账户连接、下单与成交回执仍待其创建后在页面填写；公共时间接口的HTTP 200仅证明网络可达。
