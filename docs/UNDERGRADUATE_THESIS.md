# 基于 AI Agent 的量化策略回测诊断与分析系统设计与实现

本科毕业设计选题说明｜2026-10-30

以[统一文档版本5c04f4b](https://github.com/ashcinder/atlas-quant-lab/tree/5c04f4b63a8f197862b45ced818a1ee7fc977eff)为项目基础，业务实现为4be31bf。课题解决用户看到回测结果后，仍需自行排查实验可靠性问题的困难；诊断限于历史数据充分性、配置和结果稳定性。

## 一、项目已有的功能

| 已有部分 | 可复用内容 |
| --- | --- |
| 策略开发与回测 | 自然语言生成/修改代码、人工预览应用；规则及受限Python回测，提供指标、成交、费用与风控结果 |
| 研究工具 | 参数搜索、训练/测试划分、滚动验证；已有样本不足、样本外Sharpe下降等规则警告 |
| 评价与结果管理 | 六维evaluation_v1及不可评原因、版本、结果摘要；缺实盘/风格数据时不补分 |
| 运行环境 | React/TypeScript前端、FastAPI/SQLite后端及Docker交付；云AI代码辅助、测试链和受限程序Proof已有相应本地验收 |

这些功能直接复用。当前尚缺根据结果选择补充实验、核查可能原因并关联诊断证据的Agent。完整能力及边界见[当前状态](CURRENT_STATUS.md)。

## 二、学生需要完成的工作

| 工作 | 要完成的内容 |
| --- | --- |
| 诊断规范与案例 | 定义无成交、样本不足、成本敏感、样本外表现下降四类检查的条件和判断依据，准备人工可核对案例 |
| 工具适配 | 将数据检查、回测、成本对比、样本外/滚动研究封装为Agent工具；统一输入输出、错误和实验编号，按需补充信号/执行约束等中间信息 |
| 反馈驱动的Agent | 根据当前证据选择下一项检查，处理任务状态、429繁忙、超时、取消和有限重试，设总调用预算与停止条件 |
| 报告与界面 | 完成诊断入口、进度、结果与导出；每项关键结论关联实验、数据区间、策略参数、指标和判断规则 |
| 对照评价 | 实现覆盖同样四类检查、具备必要规则分支的固定工作流，比较诊断效果、耗时与成本 |

例如，无成交时优先检查信号、预热和成交约束；训练与测试差异较大时选择参数敏感性或不同窗口检查；数据不足则说明哪些判断无法完成。Agent的贡献在于根据反馈选择检查和组织证据，已有评分/警告与代码生成不重复计为新增成果。

## 三、需要完成到什么程度

| 验收项 | 完成标准 |
| --- | --- |
| 完整演示 | 使用真实模型，在平台完成“选择回测结果→执行诊断→查看实验依据→导出报告” |
| 四类诊断 | 每类都有可复现实验及人工核对依据；案例同时包含正常、无法确定原因和混合问题情形 |
| 结果可信度 | 逐项区分已确认问题、可能原因、证据不足、未发现异常；数值与工具输出一致，文字归因有证据支持，不把无成交或下降直接等同于已查明原因 |
| 异常处理 | 非法参数、数据不足、模型超时/格式错、取消、重复请求均可处理；不得无限重试或把失败显示成完成 |
| 公平实验 | 开发集与冻结测试集分离；Agent和规则基线用相同数据、工具、标准与预算上限；统计识别精确率/召回率、误报/漏报、无依据归因、证据不足比例及耗时/费用；模型任务重复运行并报告波动 |
| 交付 | 源代码、运行说明、诊断规则、案例与参考结论、实验结果、演示材料和论文 |

基础范围为单标的、日线、已有规则策略，单Agent即可。只允许自动修正格式、工具参数及明确执行错误；改变策略逻辑或研究条件需用户确认。参数探索不反复使用最终测试集，不以“修到收益变好”为目标。不要求训练大模型、执行任意Python、接实盘或开发新ZKP/TEE。允许对照实验不支持Agent优势，并分析原因。
