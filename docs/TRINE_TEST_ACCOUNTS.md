# Supervisor测试账户准备与报价

更新：2026-10-29，按QuantJudge `672e8b8` 核对。适用于你自己的隔离测试链；不会预置旧机器的私钥、余额、`.env.local`或历史订单。当前流程见 [BKC工作流](TRINE_SERVICE_WORKFLOW.md)，原2026-09-17至18日结果见 [历史验收状态](TRINE_E2E_LIVE_STATUS.json)，不作为新账号现状。

## 创建自己的测试账户

从仓库根目录执行，Node依赖安装完成后，工具在本机受限目录保存新测试密钥，只输出文件位置与公开地址，不自动领币或发送交易：

```bash
(cd contracts && npm ci && node scripts/create-test-accounts.mjs)
```

新文件位于你自己的 `$HOME/.local/share/trine-test-accounts`，文件0600、新目录0700；已有目录权限须本机核查。不要把文件内容、私钥或前端测试环境配置提交仓库/发送聊天，也不要将测试账户用于真实资金网络。服务收款只需公开地址，不把收款私钥交给后端。

## 准备网络与测试币

确认测试链ID1051和创世哈希，再通过该链支持的正规测试币流程取得余额；创建账户不等于已领币，不假定每日额度、旧余额或支付已成功。根 `./start.sh` 是一次性新链，仅适合新实验，不能用来恢复旧付款订单。持续任务使用已配置、可恢复的持久链，见 [部署网络要求](DEPLOYMENT.md#supervisor与付款恢复)。

服务端设置实际RPC、正数 `TRINE_PROOF_PRICE_BKC` 与服务方公开收款地址。配置缺失或链不可达时拒绝创建任务。前后端启动按 [README](../README.md#本地启动)；无需旧启动脚本，也不要依赖未发布的机器环境文件。

## 登录、签名和新建实验

1. 注册/登录应用，进入设置中的Supervisor账户与私钥，使用刚创建的测试签名账户及至少12字符本地解锁密码；私钥留在浏览器签名边界，后端只转发符合订单的已签名交易。
2. 查询同一网络的真实测试余额，确认资金足以覆盖价格和网络手续费；不向前端环境变量写私钥，不默认自动解锁。仓库示例含公开演示测试密钥，使用前必须将demo设为false并清空测试密钥，不能原样带入构建。
3. 创建自己的确定性策略版本。作者自用不另付费；让另一测试用户购买时，先公开并设置版本BKC报价。
4. 申请云Proof前核对程序可读性、输入范围、报价、收款地址与网络；支付成功和规范链回执确认后才排队。记录本次返回的订单、版本和Proof ID。
5. 未知结果先查询，不重建订单重复付款；失败保留原付款供重试，当前没有自动退款。暂停运行不代表已撤销交易或清仓。

## 动态Proof报价

基础单价由服务端配置，不假定历史1 BKC或0.01 BKC仍有效。倍率为 `max(1, K线数/32 × max(1, 程序节点数/64))`，结果向上取整至0.000001 BKC，另加网络手续费。若基础价为1 BKC，32根且不超过64节点为1 BKC，64根且不超过64节点为2 BKC；这是计算量代理，不是实测云账单。

订单锁定计价版本、行情/策略哈希、价格和网络身份，后续配置变化不追溯改价。当前允许3–20000根输入，不代表最大输入已在你的机器性能验收。Proof只证明受限程序在承诺输入上的执行，不证明测试币盈利、交易所来源或管理员不可读。
