# 信息披露一致性核验

入口：监管辅助 → 信息披露一致性核验。旧的 #style-review 链接继续有效。

本版检查用户从披露文件人工提取的结构化持仓表与同期底层表，不自动读取PDF、不验证原文提取准确性。双方均为用户导入，来源未独立认证。

## 演示

1. 点击“载入披露差异示例”，检查合成数据标识和数据来源。
2. 点击“对比并保存核验快照”。公司A一致；公司B数量差额-10、市值差额-100；公司C仅底层表存在。
3. 切换仅显示待核对项，查看差异。
4. 从历史核验打开报告，或导出JSON快照（包含输入明细，需妥善保管）。

## 计算口径

CSV列严格为 code,name,quantity,value，每证券代码唯一，最多5000行/500KB。数量和市值为有限非负数、不超过1e16，最多6位小数；负持仓和衍生品特殊口径暂不支持。

双方日期必须一致，且用户确认币种、单位、估值口径和代码对齐，才进行差额计算。名称不同单独提示。绝对差额大于配置容差时标记差异，等于容差时视为容差内一致。缺项不按零处理。未确认完整范围时，底层单边记录提示范围待核对，不判断披露遗漏。前十大持仓等部分披露应先筛选底层记录至对应范围。

每次提交生成新快照，历史不覆盖。当前账号仅能读取自己的最近200份报告及其详情。报告保存在 backend/.data/disclosure_review.db（实际路径由DATA_DIR配置），与风格报告隔离。API复用平台登录、来源及JSON请求检查。

API：POST/GET /api/v1/disclosure-review/reports；GET /api/v1/disclosure-review/reports/{id}。

本版无机构签名、原始附件托管、PDF解析、链上存证、监管报送或自动违规结论。导出JSON为计算快照，不是经过认证的证据。未来可加入逐项解释、原文定位与授权数据接入。
