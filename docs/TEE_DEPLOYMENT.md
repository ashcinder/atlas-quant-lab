# TEE 保密托管部署说明

本次新增代码位于 `deploy/nitro/`。目标是 AWS Nitro Enclaves，不能直接把其他品牌的“机密虚拟机”当作同一种部署环境。

## 当前可交付内容

- 作者本地命令行打包：读取本地 Python 策略、私有签名密钥、指定运行实例配置；验证登记承诺后进行 AES-256-GCM 加密。普通平台服务器只收到密文。
- 独立作者账号持有 KMS 密钥；平台角色没有修改密钥政策权限。固定 PCR0/1/2，禁止无远程证明和测量值不匹配的解密。
- Enclave 内生成 RSA 密钥并向真实 NSM 取得证明。KMS 仅将数据密钥重新加密给该 RSA 公钥，父机只转发密文。
- 解密与签名控制器位于 Enclave 内，Python 策略子进程不接触 KMS/签名密钥。使用独立低权限 UID、seccomp、内存/CPU/输出限制；只允许经过格式校验的目标仓位离开，错误统一返回失败。
- 已接现有 `/api/v1/private-runner/signals` 协议：策略中心登记公开元数据 → 订阅 → 策略交易创建实例 → 作者下载配置并本地加密 → Enclave 持续发送绑定该实例的信号 → 现有模拟成交与资产账本。
- 提供 EC2 CloudFormation、镜像/EIF 构建脚本、持续运行服务和作者侧政策生成器。

这是一条**部署准备完成、真实硬件待验收**的路径，不是当前已经启用的 TEE 服务。本地没有真实 NSM，Docker Hub 本次又连接超时，完整 Linux 镜像/沙箱测试和云端闭环不能宣称通过。

## 以后部署的顺序

1. 使用 `deploy/nitro/host.yaml` 创建 Nitro 实例。需要提供作者 AWS 账号、VPC 与子网；平台与作者账号必须独立。EC2 会收费，本次未创建。
2. 公共项目代码放到服务器 `/opt/atlas`，执行 `sudo bash deploy/nitro/setup-host.sh`，得到 EIF 与测量值。
3. 作者独立审核公共执行程序/镜像；在自己的 AWS 账号使用 `key_policy.py` 生成政策并创建 KMS 密钥。不能仅因为平台给出某个测量值就信任它。作者客户端也应来自独立审核、固定版本的本地代码。
4. 按现有私有策略流程登记公开文件、订阅并创建平台模拟实例；仅在作者本机使用 `author.py` 加密源码、密钥和该实例连接配置。只把最终 `*.nitro-package.json` 复制到平台。
5. 设置 `ATLAS_PACKAGE`、`ATLAS_PLATFORM`、`ATLAS_APPROVED_EIF_SHA256` 三项后，执行 `sudo --preserve-env=ATLAS_PACKAGE,ATLAS_PLATFORM,ATLAS_APPROVED_EIF_SHA256 bash deploy/nitro/deploy.sh run`。通过 systemd 服务可在作者关机后继续运行。

准确命令、政策参数和服务安装说明见 `deploy/nitro/README.md`。作者的首次审核和独立授权不能由平台的“一键部署”代替；**审核后启动可以一条命令完成**。

## 必须明确的范围

当前镜像支持单个标准库 Python `decide(context)` 策略，BTCUSDT 行情、10–3600 秒间隔、返回 0–1 的目标仓位。每次决策是新进程，step 仅在该 Enclave 生命周期递增；每个 Enclave/启动器只接一份策略包。尚不支持任意第三方依赖、联网 AI、GPU 模型和跨重启状态恢复。

行情由父机转发，本路径不证明行情真实。目标仓位、交易和运行时间本来就是允许公开的输出，可能用于推断行为。TEE 不消除这种推断，也不保证服务器不会断网或被关闭。

本路径复用现有 `private_runner` 身份认证，界面当前可能仍标记“开发者本地执行”；签名成功不会自动升级为 `tee_verified`。真实成交来源、实盘收益 ZKP 和云端硬件证明状态不是本部署包已完成的验收结论。

撤销 KMS 权限能阻止下一次解锁，但不能擦除已运行 Enclave 中的密钥；同时还需停用相应策略运行。遇到拒绝或不确定的订单结果，服务停止等待检查，不自动重试成交。

## 上云后的放行条件

必须实际验证：正常非调试 Enclave 解密成功；无 Recipient、调试模式、改动镜像、错误测量值、错误密文全部失败；平台无法改密钥政策；策略源码不会出现在父机磁盘/日志；作者关机后出现至少一轮真实运行产生的模拟买卖与资产变化。未通过这些验证前不能向作者承诺已经具备生产级保密托管。
