## AI 使用

1. 撤销曾经粘贴进聊天的 Key，去服务商控制台生成新 Key。
2. 右上角设置 → AI 服务 → 选择 DeepSeek 或通义千问，填写模型名和 Key。
3. 阅读并勾选数据发送授权，保存；点击“测试连接”会产生一次很小的真实 API 调用。
4. 代码页刷新 AI 状态，发送问题；或在策略画布启用审核阶段，再运行单次回测。

设置面板不会把 Key 回显；浏览器 localStorage、导出的策略 JSON 和回测请求记录都不包含该 Key。Key 在后端按登录会话隔离，内存保留最多 8 小时，后端重启后需重新填写。它不是跨设备持久凭据保险库。当前方案面向单进程本地开发，不能直接宣称支持多 worker / 多实例生产部署；部署需 HTTPS、加密凭据服务、密钥轮换和共享会话配置。

服务商端点固定，用户不能填任意 URL；不跟随重定向，不返回含敏感内容的服务商错误。模型输出进行结构校验；数量只能按权限减少，不能增加目标。AI 请求失败会中止回测。批量研究暂时要求关闭 AI。

代码助手会发送当前代码与提问。云端回测审核会发送最近最多 20 根已收盘 K 线、交易方向、信号原因与审核指令。这些数据可能泄露策略信息；该模式不提供运营者保密、TEE 或 ZKP 保证。

接口依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[百炼兼容接口示例](https://help.aliyun.com/zh/model-studio/use-bailian-in-langchain)。模型名称可按服务商当前可用列表修改。自动化测试使用模拟服务商，不代替用户实际 Key 的网络与余额验收。

## 定投为什么停止出现买点

现有 dca 信号是分期增加目标仓位的存量资金模型，不是外部持续入金模型。例如每次增加 5 个百分点、仓位上限 95%，第 19 次后目标不再提高。间隔设为 1 根日 K 线时，买点自然集中在前段。

本轮纠正了参数标签，并将口径写入回测警告。没有增加虚构入金或强制制造交易。持续入金定投需要独立现金流记账，以及区分资金加权收益和时间加权收益，尚未在策略回测中实现。其他策略不成交需要检查信号、仓位、资金与成交约束，不能仅凭买点少判断执行器停止。

## 实盘尚未完成

当前 Binance 数据源属于行情获取，不等于账户交易接入。未提供已验收的“购买策略 → A 股/OKX/Binance 实盘 → 账本对账”闭环，没有启动任何真实交易。

A 股优先考虑 miniQMT/xtquant 接入路线，可先向国金官方核实是否可开通个人 miniQMT API、资金及费用要求；不能把渠道宣传的零门槛当作官方承诺。券商官方：[QMT 产品信息](https://edu.gjzq.com.cn/main/company-overview/business-sysinfo.html)。实际实施前需要账户权限、运行环境和交易接口确认。

实盘落地还需要：凭据管理、账户只读同步、订单幂等与对账、风险限额、交易日历、A 股交易约束、断线恢复、明确的用户启停，以及真实成交与账本现金流关联。未完成这些前不应展示“实盘可用”。
