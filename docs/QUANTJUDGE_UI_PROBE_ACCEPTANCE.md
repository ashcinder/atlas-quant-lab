# QuantJudge 界面与实时策略联调验收

验收日期：2026-09-12；分支：`QuantJudge`。

## 已实现和实际运行

- 模板策略按钮改用主题背景/文字变量，修复浅色主题黑底黑字，禁用状态保持可读；浏览器实测。
- 收起侧栏后，鼠标悬浮和键盘聚焦均显示页面名称；键盘聚焦提示已截图核对。
- 行情回测与投资组合使用同一新版结果组件：紧凑指标卡、宽幅权益面积图、柔和回撤面积图、按可用宽度调整列数。行情回测放大状态已视觉验收。组合当前真实数据仅43个共同周期，未达到60周期门槛；组合视觉验收使用页面明确标注的演示数据，随后恢复自动真实数据选项。演示结果不算本次真实行情交易验收。
- 新增可发布、订阅和后台执行的 `quote_probe` 策略。版本文件位于 `strategy/examples/quote-probe/release.json`，执行算法位于 `backend/app/quote_probe.py`。每轮交替10%目标仓位和空仓，目标检查间隔10秒，网络与其他调度任务可能增加间隔。用于功能联调，不是交易所低延迟高频系统，也未验证盈利能力。
- 首次只建立报价基线；后续按新获取的币安BTCUSDT买卖报价执行平台模拟，包含费用、滑点、盘口可用数量及单次100 USDT名义金额上限。HTTP响应过期、盘口无效或两次读取失败时进入错误状态，不用缓存补成交。服务重启后重新建立基线，停机期间不制造成交。
- 本轮累计20笔成交（10买、10卖），23个权益快照；200 USDT初始资金，最终199.39868142 USDT，收益率约-0.300659%，持仓为0。前一轮8笔后遇到报价读取失败，恢复后完成新一轮12次执行并自动暂停。结果见 [运行摘要](QUOTE_PROBE_RUNTIME_RESULT.json)。
- 这些是实时行情驱动的真实后端计算和持久化记录，环境明确为 `platform_sim`，没有交易所成交ID，不能称为Binance Testnet/OKX成交。
- 交易详情自动刷新成交及净值；资产总览按实例展示来自后端的净值曲线，不将策略分配资金重复加到账户总额。

## 页面使用

1. 策略中心 → 策略市场 → 可运行策略 → “订阅10秒买卖联调策略”。
2. 策略交易 → 新建运行，选择该订阅 → “启动10秒联调”。页面明确显示BTC-USDT、平台模拟、200 USDT。
3. 策略运行 → 展开详情，查看秒级时间的信号、模拟委托、成交、净值和回撤。每轮12次执行后自动暂停，点击恢复可开始新一轮；后台服务需持续运行。
4. 资产总览查看对应策略净值曲线。已有验收实例ID：`run_8e000bb0fd174fa780`。

Binance/OKX模拟API凭据仍通过策略交易的接入模拟账户页面配置。当前账户页面检测到Binance已配置，但本次快速探针没有使用私有API下单；交易所测试执行走此前独立的 `exchange_test` 路径。

## ZKP、TEE与去中心化的实际边界

| 部分 | 当前代码能力 | 尚未成立的承诺 |
| --- | --- | --- |
| ZKP | `backend/app/zkp.py` 验证固定image ID的RISC Zero receipt，支持受限程序/私密witness及公开结果绑定 | 不证明任意上传Python策略，也不自动证明交易所输入真实或账户完整收益 |
| TEE | `backend/app/tee.py` 校验Nitro证明的证书、签名、PCR、nonce和绑定，返回 `performance_verified=False` | 当前普通策略runner未因此变成生产TEE机密执行系统 |
| 上传策略 | `strategy_studio.py` 使用平台密钥AES-GCM加密保存，并在服务端解密 | 平台主机管理员仍可读取，不能承诺对平台开发者隐藏 |
| Supervisor | RPC客户端、外部钱包签名及证明摘要锚定路径 | 存证不等于链上执行ZKP verifier；本次没有部署链上证明验证、订阅结算合约 |
| 网站与交易 | 后端登录、数据库、订阅、调度、交易所接入 | 这些仍是中心化服务，不是完整去中心化网站 |

要达到对平台开发者也隐藏策略的目标，还需要客户端加密、经远程证明后才能释放密钥的TEE执行环境、行情/成交输入来源绑定，以及覆盖所宣称收益计算的证明程序。链上应登记策略承诺和版本、订阅权限、报告/证明与防重放状态，并执行适配该链的验证及结算合约；源码、API secret和完整witness留在链外。当前独立可验证证明与外部钱包签名是已有组件，不能据此宣称整个平台已去中心化。
