## 必须完成：作者显式授权 TEE 托管

- [ ] 提供可信、可固定版本及校验的本地开发/打包客户端；源码上传前加密，普通网站、日志、数据库只接收密文或公开资料。普通网页开发模式不能标为管理员不可读。
- [ ] 托管前由作者手动同意一份具体授权：策略及版本承诺、认可执行镜像和测量值、运行用途、输出范围、有效期、更新与撤销条件。
- [ ] 同意动作必须落实到作者独立控制的密钥政策/可验证授权，不能只是在平台数据库写 approved=true。平台不能单方批准新镜像或修改释放条件。
- [ ] TEE 内生成接收密钥对，私钥不离开隔离环境；远程证明绑定接收公钥。密钥服务验证真实证明和作者认可测量值，仅向该公钥加密交付策略数据密钥。
- [ ] 区分作者钱包私钥、策略数据密钥和 TEE 接收私钥，禁止把作者钱包私钥上传给平台或 TEE。
- [ ] 完成真实 Nitro 的正常解锁及反例验收：错误镜像/公钥/证明、debug、无证明、错误密文均拒绝。作者关机后持续执行；源码不出现在父机磁盘、内存可见接口或日志。跨重启状态恢复与防回滚另行实现和验收。
- [ ] 将通过真实证明的运行实例与前端证据状态绑定，普通签名信号不能自动标成 TEE 已验证。

现有准备代码：deploy/nitro/。真实硬件闭环未验收，不能仅租服务器后就视为完成。

## 必须考虑：人民币 / BKC 两种订阅支付

- [ ] 用户可用人民币法币支付或 BKC 支付策略订阅。
- [ ] 人民币走实际支付服务及可信支付回调；不能用前端成功提示作为到账依据。
- [ ] BKC 路径要求作者和使用者连接 BrokerChain 钱包并交互；需确认部署网络、创世身份、RPC、原生币/代币形态及合约。现有本地 Supervisor 链 ID 1051 不足以唯一识别目标网络。
- [ ] 钱包连接/签名登录与付款交易分别处理；私钥留在钱包。
- [ ] 支付订单绑定策略版本、买卖双方、金额、币种、期限和唯一订单号。两种支付成功均产生统一订阅权益；重复回调/交易不能重复发放。
- [ ] BKC 支付确认需要实际链回执、收款目标、金额、订单内容及最终性检查；订阅付费、作者分成、到期、退款、重复支付与撤销规则待设计实施。
- [ ] 人民币与 BKC 的标价/换算规则尚未确认，不自行假定自动兑换或固定汇率。

上述支付能力尚未完成，不将现有策略摘要存证当作支付合约。
