# 外观、行情库、定投与账户连接（2026-09-09）

## 操作入口

- 右上角设置 → 外观：纯白、雾蓝、深蓝、石墨、墨绿；蓝、青绿、金色强调色。K 线和权益图同步切换底色。
- 左下角“切换工作区”：展开后有“× 收起”；点击外部、按 Escape 或切换页面也会关闭。
- 行情与回测 → 策略模板 → 资金计划 · 定期定额（固定金额）。旧规则另名“分期建仓（旧版）”，历史结果和用户参数不做静默迁移。
- 设置 → 交易所账户连接：Binance 现货／OKX 交易账户的只读连接验证。此入口**不执行订单**。

## 固定金额定投

例如初始资金 100000、每次 1000、间隔数量 1、间隔单位“周”。按已完成 K 线确认到期，下一根开盘买入，1000 包含手续费；滑点和价差影响实际数量。

时间按 UTC 日历计算。月末锚点不会永久漂移：1 月 31 日 → 2 月末 → 3 月 31 日。K 线粗于计划频率时，多次到期合并为该根确认的一次，不虚构根内成交。要研究每日定投，应选日线或更细周期，不能用周线还原每天的成交。

资金来自已有现金，不会生成外部入金。现金、仓位上限、流动性或 AI 审核可能减少／阻止买入；不是保证每次足额成交。当前尚无自动向券商充值的功能。

## 行情数据库

实际位置：`backend/.data/cache/market.sqlite3`。SQLite WAL 模式、事务式快照替换；表 `snapshots` 保存更新时间，`candles` 保存时间和 OHLCV。键隔离数据源、标的、周期、复权及请求范围；同一 K 线在不同请求快照中可能重复，行数不等于去重后的市场 K 线数量。

已把 43 份原有真实缓存（54794 个快照行）迁入库；保留旧 gzip 文件，排除 demo 文件。22 个默认标的的日线预加载均已成功。本次没有声称下载了所有周期、所有上市历史。

命中有效缓存不访问外网；过期后通常只取尾部三根重叠段进行增量合并。非加密资产每天重新取得所请求历史，以降低复权变化造成的新旧口径混合风险。来源失败时返回显式 stale 标记，不以演示行情冒充真实数据。更新按读取触发，不是后台全市场实时数据服务。

从 backend 目录手动预热／更新默认日线：

```sh
.venv/bin/python -m app.data.warm_cache
```

数据来源：加密 Binance，股票／ETF 等使用项目现有 Sina 与 Yahoo 后备，港股 Tencent 与 Yahoo 后备。第三方免费行情并不等于交易所授权的机构级数据 SLA；机构部署仍需要数据授权、公司行为版本和停牌交易日质量监控。

已核对 [Binance 官方历史数据仓库](https://github.com/binance/binance-public-data)：提供历史 K 线归档。当前实现使用现有 REST 提供器及数据库，**尚未增加月度 ZIP 全历史下载器**。

## 账户连接的真实进度

已实现：登录会话隔离、8 小时内存凭证、允许的 Binance／OKX 连接、只读余额、30 秒读取限流、错误脱敏、清除连接。OKX 需要 Key、Secret、Passphrase。仅使用只读权限，不启用提现。配置成功不表示验证成功，需由用户点击“读取真实余额”。服务重启后需重新填写。当前只适合单进程本地验证，不适合无人值守托管。

自动化测试使用模拟交易所客户端，**没有真实账户凭证验收，也没有真实下单**。余额快照不是收益报告，没有自动写入资产账本，以免重复计入资产。

未完成：订阅权限绑定策略执行版本、持续运行 worker、真实订单提交／撤单、幂等与超时对账、成交与现金流入账、实盘净值证明。页面不应宣称“订阅后即可实盘”。

A 股应使用券商授权的 MiniQMT／其他官方接口。根据 [迅投官方说明](https://dict.thinktrader.net/nativeApi/start_now.html)，XtQuant 调用前必须启动 MiniQMT 客户端。当前没有用户的券商终端和权限，尚未完成 A 股实盘联调；不能用通用账号密码绕过券商接入要求。
