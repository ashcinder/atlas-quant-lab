# A 股规则统一：实现状态与执行约定

状态：**研究基础代码，尚未接入网页或三个回测引擎**。不要把本文件列出的目标当成当前功能。

当前三个执行器的数据、预热、调仓和撮合规则不同；选择同一个标的并不会自然得到同一个收益。若需要逐笔一致，至少要固定行情及复权方式、预热区间、信号生成时点、下一根开盘成交、订单与部分成交规则、费用、公司行动、价格精度和舍入规则，并对每个引擎比较每一笔委托、成交、现金及持仓。每个引擎的原生规则不一致时，不能只修改结果数字，也不能把单个引擎的结果冒充三个独立引擎的结果。

## 当前已完成的基础代码

`backend/app/backtest/cn_rules.py` 提供独立规则原语：接收上游提供的交易日、未复权开盘价、历史涨跌停价、停牌状态和可卖库存，判断 T+1、申报数量及涨跌停方向限制；提供单笔成交的最低佣金和按日期调整的卖方印花税计算。原语不读取行情、不维护持仓账本，也不会被任何实际回测调用。

测试覆盖 T+1 可卖数量、主板整百股、科创板单笔至少200股及1股递增、清仓零股、涨停买入/跌停卖出拒绝、停牌、缺失历史涨跌停信息，以及 2023-08-28 前后的印花税。

行情数据必须区分：历史涨跌停信息未知，以及交易所明确规定当日无涨跌幅限制。不能把前者当后者，也不能简单按前收盘价乘固定比例计算；除权除息、风险警示状态、板块及规则生效日期均会影响真实价格限制。

## 尚需完成

1. 在行情发布格式中保存并校验原始 OHLC、交易日、历史涨跌停价、停牌及公司行动；确保各类周期和标的具备可靠覆盖。缺失时应向用户说明并停止使用严格规则，不能静默降级或伪造价格。
2. 定义并实现带交易日可卖库存的持仓账本、拆分与分红、订单部分成交与逐单最低佣金、合理的撮合及成交量假设；明确日线无法还原的竞价盘口和排队细节。
3. 将相同约定分别接入 Atlas、vn.py、RQAlpha 的真实执行路径，针对相同的信号和价格逐笔核对。保持原生框架身份与不同规则的差异可追踪。
4. 在网页提供明确的开关，A 股默认开启，比特币等非 A 股不应用；后台独立验证请求。保存到回测请求和结果，重新打开历史记录时应能看到所用规则版本。
5. 用真实股票历史及带边界情况的测试数据执行端到端测试，包括同日买卖、跨日可卖、停牌、涨跌停、退市与公司行动、科创板、历史税费、数据缺失及关闭规则后的行为。
